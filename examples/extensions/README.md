# Java extension examples

This development module depends on `:parser`; its Java sources contain no Gradle API.
It is not a dependency of the Gradle plugin and is not published.

- `ChannelPrefixRule` checks typed channel addresses against the `prefix` text parameter.
  It resolves aliases and reports one definition diagnostic with related usage locations.
- `ChannelCatalogGenerator` resolves typed channels and writes a sorted JSON catalog.
  `file` selects its relative output path (default `channels.json`); output uses UTF-8 and LF.
- `ExampleMain` parses an input, registers both extensions by binary class name and executes them.

From the repository root, using the unpublished model `.5` staged according to the
[source-build instructions](../../README.md#build):

```powershell
.\gradlew.bat :extension-examples:runExample '-PasyncwrightModelRepository=C:/path/to/model-repository' --configuration-cache-problems=fail
```

Input: `examples/extensions/events.yaml`. Output:
`examples/extensions/build/generated-example/catalog/channels.json`:

```json
{
  "created" : "events.demo.created",
  "updated" : "events.demo.updated"
}
```

The same `ExampleMain` is an ordinary Java entry point accepting two arguments:
the specification path and the output directory. With the example jar, parser jar and their
runtime dependencies on the classpath, it runs directly via `java`; the Gradle task is a convenience host.

`check` runs the example tests: exact generated bytes, reference preservation, definition/use
diagnostics, skipped generation on a rule error, and the standalone entry point.
The parent [extension API contract](../../docs/extensions.md) describes loading and failure behavior.
